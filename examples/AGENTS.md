# Working with vwork and host tools

- **Reads are unrestricted by vwork policy.** Read any accessible host file, including skills, AGENTS.md and files inside existing repositories. Use vwork reads for the current virtual source; host files may contain a different revision.
- **Keep repository work in vwork by default.** Reuse registrations; use repo_clone/repo_register for setup and repo_fetch for updates. Persistent Git objects and source live in redb. Fetch leaves existing workspaces pinned; create a workspace from the updated ref when needed. Do not create unmanaged clones, worktrees, Git object stores or bulk source copies on disk.
- **Use host tools for other work.** Other MCPs (including web search and AWS), host-file edits, and one-off Bun/Python/shell scripts are allowed. Skills and global AGENTS.md can be edited on disk. Keep disposable scripts/output in a small temporary directory and clean it up when done. Do not use scripts to bypass the repository workflow. Normal user instructions and service permissions still apply.
- **Use temporary copies when a repository tool requires real files.** Prefer configured package_run (npm/Cargo/pip/uv/CDK) or workspace_run_task. Otherwise request workspace_temporary with a purpose and run the needed tool there. Import wanted edits with explicit paths and the returned revision, save wanted artifacts, then temporary_release promptly. Renew before expiry if still needed; temporary_list shows forgotten copies and cleanup errors. Expiry/restart cleanup preserves bounded nonignored source edits in a recovery workspace, then deletes the copy and disposable dependencies/outputs. External shell jobs must finish before release/expiry. Use discard_changes only to intentionally discard edits.
- **Durable exports are allowed.** Use workspace_export for an intentional on-disk copy that should remain available. Exports have no expiry; report their location and retain them as needed. Prefer temporary copies for transient build/tool work.
- **Keep virtual edits consistent.** Get workspace_info before editing and supply expected_revision; reread and reconcile conflicts. Use virtual file, search, diff, history and merge tools. files_apply_patch takes full-file replacement/deletion objects. Import source changes explicitly; never import dependency directories or caches. Use storage_info for shared storage questions instead of creating probe workspaces.
- **Report actual outcomes.** Check tool results and exit status; identify tested revisions and unresolved cleanup. Missing configured tasks do not prohibit general host tools or filesystem-only work in a temporary copy. CDK package actions cover local synth/list; use normal service tools and user authorization for cloud operations.
